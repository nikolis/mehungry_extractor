# Phase 2 — Deterministic entity extraction + normalization

**Goal:** find biomedical entity mentions in the canonical text and normalize them to
controlled-vocabulary concepts — deterministically, with an exact-span `EvidenceRef` on
every mention. This is the first layer that produces "knowledge", so provenance discipline
starts here.

**Prerequisite:** Phase 1 (`phase-1-foundation.md`). You consume `Document`/`Sentence`
objects and their offsets; you do **not** re-parse XML.

## Deliverables

### Modules
- `knowledge/entities.py` — mention extraction over a `Document`.
- `knowledge/normalize.py` — surface form → normalized concept (vocabulary linking).
- `knowledge/vocab/` — bundled deterministic dictionaries/ontology maps (checked in, or
  generated by a checked-in, versioned build script). This is where determinism lives.

### Entity types (start small, expand deliberately)
`disease, symptom, drug, chemical, nutrient, food, intervention, biomarker, outcome,
anatomy, organism`. Begin with the types scispaCy models emit well (chemical, disease) plus
dictionary-driven `nutrient`/`food` (highest value for Mehungry), then grow.

### Data model (pydantic, mirrors spec §6)
`EntityMention`: `surface_text, normalized_text, entity_type, start_char, end_char,
sentence_id, normalization_source, status` + `evidence_ref: EvidenceRef`.
`EntityConcept` (the normalized target): `concept_id, canonical_name, vocabulary,
entity_type`. A mention links to a concept but always keeps its surface form.

### DB tables (`knowledge/db/schema.py`)
- `entities` — one row per distinct normalized concept (`concept_id` PK, `canonical_name`,
  `vocabulary`, `entity_type`).
- `entity_mentions` — `mention_id` PK, FKs to `document_id`/`sentence_id`/`concept_id`
  (nullable when unnormalized), `surface_text`, `start_char`, `end_char`, `entity_type`,
  `normalization_source`, `status`, `run_id`. Index on `document_id`, `concept_id`,
  `sentence_id`.
- Add a `persist_entities(session, document, mentions, run)` (delete-then-insert per
  document, parents before children — mirror `persist_document`).

### CLI
Implement the `analyze` stage in `knowledge/stagecli.py` (replace the stub):
`mehungry analyze --document pmid:NNNN` → load canonical doc, extract + normalize entities,
persist. Independently rerunnable.

### Query
Add `list_entities_for_document(engine, doc)` and `find_mentions(concept_id=...)` to
`knowledge/query.py`.

## Provenance constraints (offline; determinism optional)
- **scispaCy is deterministic at inference** (fixed weights, greedy decoding — no sampling).
  Pin the exact model wheel + version and record it in `ExtractionRun.ontology_versions`
  (and `scispacy_version`, already captured). Load with a cached singleton like
  `segment._nlp()`; disable components you don't use.
- **Keep dictionary/exact matching as the backbone**; use scispaCy (and, now, any **local**
  model) as a candidate generator. Exact/dictionary matches are the transparent, auditable floor;
  keep the model optional and behind the same "no-op if unavailable" degradation as `ner.py`.
- **Normalization must be offline; it no longer has to be deterministic.** A **local** embedding
  or similarity resolver may now link surfaces the dictionary missed (e.g. "cholecalciferol" →
  "vitamin D"), provided the mention keeps its `EXACT_SPAN` and records how it was resolved (the
  matched concept + score). The scispaCy UMLS/MeSH linker is still fine if pinned and treated as a
  versioned KB artifact; curated dictionaries under `knowledge/vocab/` remain the backbone. Hosted
  linking APIs stay out (online).
- Every mention gets `EvidenceRef` with `precision=EXACT_SPAN`. Add
  `EvidenceRef.for_span(...)` in `provenance.py` for sub-sentence spans (find the owning
  sentence from the mention offsets). `extraction_rule` = the extractor/dictionary id;
  `extraction_rule_version` = its version.
- `status` records normalization outcome (`normalized | ambiguous | unmatched`) — never drop
  a mention just because it didn't normalize; keep it with `status=unmatched`.

## Suggested steps
1. Add `scispacy` to core deps or keep in `[ner]`; document the model download. Add
   `EvidenceRef.for_span`.
2. Build the vocab layer (`knowledge/vocab/`) + `normalize.normalize(surface, entity_type)`.
3. Build `entities.extract(document) -> list[EntityMention]` (dictionary + optional scispaCy),
   offsets rebased to absolute via each sentence's `start_char`.
4. Add tables + `persist_entities` + `analyze` stage + query helpers.
5. Tests, then stop (gate Phase 3).

## Tests to add (gate)
- **Offset reconstruction:** `document.text[m.start:m.end] == m.surface_text` for every
  mention.
- **Normalization mapping:** known surfaces map to expected concepts; unmatched surfaces get
  `status=unmatched` and no invented concept.
- **Determinism:** run twice on a fixture → identical mention list (ids, offsets, concepts).
- **Dictionary hits:** synthetic sentences with nutrients/foods produce the expected types.
- Do not require network; use fixtures. If a scispaCy model isn't installed, the dictionary
  path must still produce deterministic results (mirror `ner.available()`).

## Done criteria
`mehungry analyze --document pmid:NNNN` persists entity mentions with exact spans and
normalized concepts; every mention is reconstructable from offsets; the run records the
model/vocab versions; two runs are byte-equivalent. Bump `RULESET_VERSION` (e.g. `0.1.0`)
and `SCHEMA_VERSION`.
